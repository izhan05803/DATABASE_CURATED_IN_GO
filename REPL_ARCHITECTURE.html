📋 What is REPL.GO?

REPL.GO is the orchestrator and motherboard of the GoFromScratchDB CLI. It coordinates all components and controls the flow of data through the system.

Metaphor: The Motherboard

Just like a computer motherboard:

  • Doesn't do the work: CPU (engine), RAM (parser), GPU (formatter) do the actual work
  • Connects everything: Buses route data between components
  • Controls flow: Chipset manages timing and sequencing
  • Handles I/O: Ports connect to external world (terminal/user)
  • Manages state: Tracks active components (engine, history)
💡 Key Insight: Remove REPL.GO and the system breaks. Engine could still do Get/Set (but no user interface), Parser could still parse (but no one feeds it data), Formatter could still format (but no one calls it). REPL.GO ties everything together.

Detailed Steps

Step 1: INITIALIZATION
When REPL.Start() is called:
  • Create bufio.Scanner for reading stdin
  • Initialize Engine (loads database)
  • Create History buffer (capacity: 100)
  • Enter infinite for loop
Step 2: READ INPUT
Display prompt and wait for user:
  • fmt.Fprint(out, "godb> ")
  • scanner.Scan() - blocks until user hits Enter
  • Trim whitespace
  • Skip if empty
Step 3: PARSE
Convert raw text to Command struct:
  • Input: "SET key1 value1"
  • Output: Command{Type: "SET", Args: ["key1", "value1"]}
  • If parse fails, show error and loop
Step 4: VALIDATE
Check if command is valid:
  • Is Type a known command? (GET, SET, DELETE, etc)
  • Does it have correct # of arguments?
  • If invalid, show error with usage hint and loop
Step 5: SAVE TO HISTORY
Only if parse succeeded:
  • history.Add(line)
  • Ring buffer stores last 100 commands
  • Automatic FIFO eviction when full
Step 6: EXECUTE
Run command against engine:
  • execute(db, cmd) called
  • Switch on cmd.Type
  • Call appropriate db.Get/Set/Delete/etc
  • Capture result and any error
Step 7: FORMAT
Make output beautiful:
  • KEYS → formatKeysList() - aligned columns
  • INFO → formatInfoOutput() - boxes & sections
  • HELP → formatHelpOutput() - documentation
  • Others → Just the message
Step 8: PRINT RESULT
Output to terminal:
  • fmt.Fprintln(out, result.Message)
  • User sees: "✅ OK" or error or formatted data
Step 9: CHECK EXIT
Should we continue?:
  • if cmd.Type == "EXIT" { break }
  • Otherwise: Loop back to Step 2
  • On exit: db.Close() to clean up

🎯 REPL.GO's Core Responsibilities

1. INPUT/OUTPUT ORCHESTRATION
  • Read user input via bufio.Scanner
  • Display prompts ("godb> ")
  • Print results to output stream
  • Manage I/O with external world
2. ROUTING / DISPATCH
  • Route raw text to Parser
  • Route commands to Validator
  • Route validated commands to Engine
  • Route results to Formatter
3. ERROR HANDLING
  • Parse errors → Show syntax help
  • Validation errors → Show usage hints
  • Execution errors → Show context
  • All with emoji indicators (❌)
4. STATE MANAGEMENT
  • Create and maintain History object
  • Create and maintain Engine (database)
  • Track main loop state (running/exit)
  • Resource cleanup (db.Close())
5. FORMATTING & PRESENTATION
  • formatInfoOutput() - Box drawing, sections
  • formatHelpOutput() - Command documentation
  • formatValidationError() - Helpful suggestions
  • formatErrorMessage() - Error context

🔍 Analysis: Notice how each component has a distinct responsibility. REPL.GO doesn't do any of these things—it just coordinates them. This is the "separation of concerns" principle in action.

💻 Code Examples

Main Entry Point: func Start()

func Start(in io.Reader, out io.Writer) error { scanner := bufio.NewScanner(in) db, err := engine.NewPersistent(defaultDBPath) if err != nil { return fmt.Errorf("start persistent engine: %w", err) } history := NewHistory(historyCapacity) for { // 1. Show prompt fmt.Fprint(out, prompt) if !scanner.Scan() { break } // 2. Read input line := strings.TrimSpace(scanner.Text()) if line == "" { continue } // 3. Parse p := parser.NewParser(line) cmd, err := p.Parse() if err != nil { fmt.Fprintf(out, "❌ %s\n", formatErrorMessage("parsing error", err.Error())) continue } // 4. Validate if err := parser.ValidateCommand(cmd); err != nil { fmt.Fprintf(out, "❌ %s\n", formatValidationError(cmd.Type, err.Error())) continue } // 5. Save to history history.Add(line) // 6. Execute result := execute(db, cmd) // 7. Print printResult(out, result) // 8. Check exit if cmd.Type == "EXIT" { break } } return db.Close() }

Execute Function: Dispatch to Engine

func execute(db *engine.Engine, cmd *types.Command) *types.Result { switch cmd.Type { case "GET": value, err := db.Get(cmd.Args[0]) if err != nil { return &types.Result{Success: false, Message: "❌ GET key not found"} } return &types.Result{Success: true, Message: fmt.Sprintf("%q", string(value))} case "SET": err := db.Set(cmd.Args[0], []byte(cmd.Args[1])) if err != nil { return &types.Result{Success: false, Message: fmt.Sprintf("❌ SET failed: %v", err)} } return &types.Result{Success: true, Message: "✅ OK"} // ... more cases ... default: return &types.Result{Success: false, Message: fmt.Sprintf("❌ Unknown command: %s", cmd.Type)} } }

Error Formatting: Three Layers

// Layer 1: Parsing Error func formatErrorMessage(context, message string) string { return fmt.Sprintf("%s: %s", context, message) } // Layer 2: Validation Error (with suggestions) func formatValidationError(cmd, message string) string { suggestions := map[string]string{ "GET": "Usage: GET key", "SET": "Usage: SET key value", "DELETE": "Usage: DELETE key", // ... more commands ... } msg := fmt.Sprintf("%s: %s", cmd, message) if suggestion, ok := suggestions[cmd]; ok { msg += fmt.Sprintf("\nℹ️ %s", suggestion) } return msg }

Example: HTTP REST API (Replaces REPL.GO)

// Instead of REPL.GO reading from terminal: func handleHTTPPost(w http.ResponseWriter, r *http.Request) { // 1. Parse HTTP request body var req struct { Command string } json.NewDecoder(r.Body).Decode(&req) // 2. Use same parser! p := parser.NewParser(req.Command) cmd, err := p.Parse() // 3. Use same engine! result := execute(db, cmd) // 4. Use same formatter! message := formatOutput(result) // 5. Return as JSON instead of terminal w.Header().Set("Content-Type", "application/json") json.NewEncoder(w).Encode(message) }
💡 Design Pattern: This is the Adapter Pattern. REPL.GO is just one adapter. You could have HTTPAdapter, TCPAdapter, WebSocketAdapter—all using the same Engine/Parser/Formatter underneath.

📌 Summary

What is REPL.GO?

REPL.GO is the orchestrator/motherboard that ties all components together. It:

  • Reads input from the user (scanner)
  • Routes commands to Parser → Validator → Engine
  • Handles errors with context and suggestions
  • Stores state (History, Engine)
  • Formats output to be beautiful and readable
  • Manages flow through the main event loop

Why is REPL.GO Important?

  • Separation of Concerns: Each component has one job
  • Testability: Can test Engine without REPL.GO
  • Reusability: Engine can be used by HTTP API, TCP server, etc
  • Maintainability: Changes to one component don't affect others
  • Scalability: Can replace REPL.GO with HTTP router without touching Engine

Interview Talking Point

🎤 How to explain REPL.GO:

"REPL.GO is the orchestration layer that coordinates between user input and the database engine. It's like the motherboard of a computer—it doesn't do the actual work (that's the engine), but it connects all the pieces and controls the flow. The key design insight is separating concerns: the engine handles business logic, the parser handles text, the formatter handles output, and REPL.GO just coordinates them. This makes the code testable, reusable, and easy to extend—you could swap REPL.GO for an HTTP router and suddenly you have a REST API using the same engine."
